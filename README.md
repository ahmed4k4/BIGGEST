# BIGGEST — Fashion Collection · نظام إدارة محل الملابس الرجالي

ستة مشاريع منفصلة، كل مجلد يعمل ويُركَّب بمفرده ولكل منه `README.md` يشرح ما هو وأين يوضع وكيف يُركَّب.

| المجلد | ما هو | أين يُركَّب | يحتاج |
|---|---|---|---|
| `1-database` | قاعدة البيانات ومنطق الأعمال | Supabase (مجاني) | حساب Supabase |
| `2-api` | الواجهة الخلفية | Cloudflare Workers (مجاني) | 1 |
| `3-admin-dashboard` | لوحة الإدارة | Cloudflare Pages | 2 |
| `4-online-shop` | المتجر الإلكتروني | Cloudflare Pages | 2 |
| `5-branch-pos` | الكاشير والطابعة (يعمل بدون إنترنت) | كمبيوتر كل فرع | 2 + Node 22.13+ |
| `6-backup-server` | النسخ الاحتياطي وتصدير Excel | جهاز دائم التشغيل بالمحل | 1 + 2 + أدوات pg |

## ترتيب التركيب
1. `1-database` ← 2. `2-api` (وأنشئ المدير بـ `create-owner`) ← 3. `3-admin-dashboard` و`4-online-shop` ← أنشئ أجهزة الفروع من الإدارة ← 4. `5-branch-pos` لكل فرع ← 5. `6-backup-server`.

عنوان الـ API هو الرابط الذي تضعه في بقية البرامج. كل برنامج يتصل بالـ API فقط، ولا يتصل بالقاعدة مباشرة (عدا النسخ الاحتياطي).

## مجلدات إضافية (للمطوّر فقط، ليست للتركيب)
- `shared/` الكود المشترك؛ يُنسخ تلقائيًا داخل كل مشروع (`tools/sync-shared.mjs`) ليبقى كل مجلد مستقلًا.
- `tools/` الاختبارات والتشغيل المحلي والتغليف. `docs/` الشرح المعماري ودليل المستخدم. `assets-brand/` الشعار.

## ملاحظات صريحة
لم تُجرَّب على أجهزة حقيقية: الطابعات الفعلية، تطبيق Electron، ملفات `.bat` وتشغيل ويندوز التلقائي، والنشر على Cloudflare/Supabase الحقيقيين. جرّبها في فرع واحد قبل التعميم.
