# 0001 — منطق الأعمال في دوال PostgreSQL

**السياق.** الـ API على Cloudflare Workers (حدود زمن/ذاكرة، ولا اتصال TCP دائم بـ Postgres) وSupabase يُكلَّم عبر PostgREST. البيع والحجز والمزامنة تحتاج ذرّية.

**الخيارات.** (أ) منطق في الـ API مع طلبات متعددة. (ب) منطق في دوال SQL والـ API رقيق. (ج) ORM/خادم تقليدي.

**المجلس.**
- *المعماري:* (ب) معاملة واحدة لكل عملية؛ لا سباق بين طلبين على آخر قطعة.
- *المشغّل:* لا يهمه المكان، يهمه ألا تتكرر فاتورة ولا يُباع ما ليس موجودًا.
- *المتشكك:* SQL أصعب في الاختبار والإصدار. ← نقابله باختبارات على PostgreSQL حقيقي ومهاجرات مرقّمة.
- *المالية:* (ب) يقلل طلبات Workers (حد 100k/يوم مجانًا).

**القرار.** (ب). الـ API يتحقق من الصلاحية والمدخلات ويستدعي RPC. سائق قاعدة البيانات قابل للتبديل (psql/pg/PostgREST) فتعمل الاختبارات بلا مكتبات.

**المقايضة.** تقييد بـ PostgreSQL؛ لكن الأصل مطلوب (Supabase).
